# Project Scope

## North Star

Hell X should prove a compact online horror slice that is playable, persistent, and easy to evaluate. The project should make it clear how the player experience, backend data flow, testing, and milestone evidence fit together.

## Product Promise

Players can enter a short 2D horror chapter, explore a tense space, interact with objects, solve simple puzzle beats, and return later with progress intact. The slice should be small, but it should feel like the foundation of a complete game.

## Protected Priorities

- Build a horror game first, not a technology showcase.
- Keep the first slice small enough to finish and test.
- Protect save/resume reliability as a core product requirement.
- Keep player state server-backed where persistence matters.
- Maintain clear docs, issue tracking, review flow, and milestone evidence.
- Avoid speculative systems until the vertical slice is stable.

## P0 Features

- Unity 2D WebGL client foundation.
- Basic playable room flow.
- Player movement and interaction.
- Login/session direction.
- Cloud save and resume direction.
- Backend API foundation.
- PostgreSQL and Prisma persistence direction.
- Project documentation, process, and templates.
- Demo script and evidence plan.

## P1 Features

- Inventory state.
- Puzzle state.
- Journal and lore progression.
- Deaths, settings, and unlocks.
- QA/Ops dashboard for player, session, and save visibility.
- More complete test coverage.
- CI workflow once core commands are stable.
- Improved atmosphere, UI feedback, and demo polish.

## Explicitly Out Of Scope

- Blockchain features.
- NFT features.
- Wallet login.
- Smart contracts.
- Marketplace systems.
- Tokenomics.
